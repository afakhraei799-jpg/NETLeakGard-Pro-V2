# NETLeakGuard Pro V2 — سامانه ممیزی و تشخیص نشت شبکه (ویرایش فارسی و انگلیسی)

**NETLeakGuard Pro V2** یک ابزار تخصصی و مبتنی بر شواهد (Evidence-Based) برای بررسی نشت آدرس IP، نشت DNS، نشت نامزدهای WebRTC ICE، طبقه‌بندی احتمالی ASN/VPN، بررسی پورت‌های حساس TCP روی آدرس خروجی و اندازه‌گیری تاخیر (HTTP RTT) است.

> **اصل بنیادین طراحی:** صحت نتایج امنیتی بر ظاهر و سرعت اولویت مطلق دارد. این نرم‌افزار هرگز وضعیت‌های `ERROR`، `INCONCLUSIVE`، `UNSUPPORTED` یا `NOT_CONFIGURED` را به `PASS` («موفق / بدون نشت») تبدیل نمی‌کند و هیچ‌گاه نبود اطلاعات یا عدم پاسخ شبکه را به‌منزلهٔ امن بودن اتصال تلقی نمی‌کند.

---

## ۱. قابلیت‌های واقعی سیستم

1. **بررسی چندمنبعی آدرس IP عمومی و GeoIP (`fetchIpDetails` و `/api/ip-info`):**
   - مقایسهٔ آدرس مشاهده‌شده از مرورگر کلاینت (`api64.ipify.org` و `ipwho.is`) با آدرس مشاهده‌شده در سوکت سرور برنامه.
   - تشخیص هوشمند اتصالات دوپشته (**Dual-Stack IPv4/IPv6**): تفاوت خانوادهٔ آدرس (IPv4 در برابر IPv6) به‌عنوان نشت کاذب گزارش نمی‌شود و فقط مغایرت در **یک خانوادهٔ آدرس یکسان** به‌عنوان `LEAK_DETECTED` (احتمال Split-Tunneling یا پروکسی انتخابی) علامت‌گذاری می‌گردد.
   - اعتبارسنجی سخت‌گیرانهٔ هدرهای پروکسی (`X-Forwarded-For` / `CF-Connecting-IP`) فقط در صورت فعال بودن `TRUST_PROXY=true` و اتصال از سوکت پروکسی داخلی، با انتخاب **راست‌ترین آدرس IP عمومی معتبر** جهت جلوگیری از جعل هدر (XFF Spoofing).

2. **تفکیک کامل تست Authoritative DNS و مشاهدهٔ کمکی مرورگر (`performDnsLeakTest`):**
   - **تست Authoritative DNS اختصاصی:** با تولید شناسهٔ یکتای رمزنگاری‌شده (`runId`) در هر اجرا و ارسال کوئری‌های ساب‌دامین غیرقابل‌حدس با قالب استاندارد `p<N>.<runId>.<DNS_LEAK_DOMAIN>` (مانند `p1.<runId>.<DNS_LEAK_DOMAIN>`). در صورت تنظیم نبودن متغیرهای سرور یا تأیید نشدن شنوندهٔ UDP/53، وضعیت صریحاً `NOT_CONFIGURED` («پیکربندی نشده») اعلام می‌شود.
   - **مشاهدهٔ کمکی مرورگر (بدون هزینه):** استعلام مستقیم از سرویس‌های عمومی EDNS و Cloudflare Trace (`1.1.1.1/cdn-cgi/trace`). مشاهدهٔ یک Resolver یا تطابق کشور در مرورگر هرگز به‌عنوان اثبات عدم نشت DNS (`PASS`) یا نشت قطعی (`LEAK_DETECTED`) تلقی نمی‌شود.

3. **تست واقعی نامزدهای WebRTC ICE (`performWebRtcLeakTest`):**
   - استخراج نامزدهای `host`، `srflx`، `relay` و شناسه‌های `mDNS` (`.local`) از طریق `RTCPeerConnection`.
   - در صورت غیرفعال بودن WebRTC (`UNSUPPORTED`) یا دریافت نشدن هیچ نامزد عمومی STUN (`INCONCLUSIVE`)، هرگز وضعیت `PASS` صادر نمی‌شود.
   - بستن ایمن `RTCPeerConnection` و پاک‌سازی تایمرها در تمامی مسیرهای عادی، خطا یا لغو.

4. **طبقه‌بندی احتمالی ASN / دیتاسنتر (`evaluateVpnHeuristic`):**
   - تفکیک کامل «تشخیص احتمالی IP دیتاسنتر» (`isDatacenterIp`) از «وضعیت نشت تونل» (`status`).
   - شفاف‌سازی صریح اینکه نوع پروتکل تونل (WireGuard، OpenVPN، IKEv2، V2Ray) و اندازهٔ واقعی MTU از لایهٔ مرورگر وب قابل اثبات فنی نیستند.

5. **بررسی پورت‌های حساس TCP روی آدرس عمومی تأییدشده (`performPortLeakTest` و `/api/port-scan`):**
   - بررسی ۸ پورت متداول (`80, 443, 8080, 8291, 22, 23, 21, 1080`) صرفاً روی آدرس IP عمومی تأییدشدهٔ کلاینت (مسدودسازی کامل پارامترهای دستی برای جلوگیری از SSRF).
   - تفکیک وضعیت‌های `open`، `closed`، `filtered_timeout` و `not_tested`. اگر حتی یکی از پورت‌های هدف در وضعیت `not_tested` باشد، نتیجه `INCONCLUSIVE` است و هرگز `PASS` صادر نمی‌شود.

6. **کرهٔ سه‌بعدی تعاملی و حالت سپر (`Globe3D.tsx`):**
   - تفکیک بصری و متنی وضعیت‌های `PASS`، `LEAK_DETECTED`، `ERROR` و `INCONCLUSIVE`.
   - اعتبارسنجی مختصات جغرافیایی متناهی در بازهٔ `lat ∈ [-90, 90]` و `lon ∈ [-180, 180]` پیش از ترسیم پین.
   - مدیریت چرخهٔ حیات منابع Three.js (`createGlobeResourceManager`)، پشتیبانی از `webglcontextlost` و حالت جایگزین ایمن در صورت عدم پشتیبانی از WebGL.

## ۲. راه‌اندازی، تست و ساخت (Build)

### پیش‌نیازها
- **Node.js** نسخهٔ ۲۰ یا بالاتر
- **npm**

### نصب وابستگی‌ها و اجرای محیط توسعه
```bash
npm install
cp .env.example .env
npm run dev
```
برنامه روی آدرس `http://localhost:3000` اجرا می‌شود.

### اجرای تست‌های واحد، بررسی نوع‌ها (TypeScript) و ساخت نسخهٔ تولید (Production Build)
```bash
# اجرای تمام تست‌های واحد خودکار
npm test

# بررسی کامل نوع‌های TypeScript بدون تولید فایل
npm run lint

# ساخت باندل نهایی فرانت‌اند در پوشه dist/
npm run build

# اجرای سرور در محیط عملیاتی
npm start
```

## ۳. متغیرهای محیطی (`.env`)

تمامی متغیرهای محیطی در فایل `.env.example` مستند شده‌اند و اختیاری هستند؛ نبود آن‌ها باعث کرش سرور نمی‌شود و قابلیت مرتبط با وضعیت شفاف (`NOT_CONFIGURED`) نمایش داده می‌شود:

| نام متغیر | اجباری؟ | توضیح و کاربرد |
| :--- | :---: | :--- |
| `PORT` | خیر | پورت اجرای سرور Express (پیش‌فرض: `3000`) |
| `TRUST_PROXY` | خیر | فقط زمانی `true` شود که سرور پشت پروکسی معکوس مورد اعتماد (مانند Cloudflare یا Cloud Run) قرار دارد |
| `DNS_LEAK_DOMAIN` | برای تست Authoritative DNS | دامنهٔ اختصاصی که رکورد `NS` آن به سرور Authoritative DNS شما اشاره می‌کند (مثال: `dnsleak.example.com`) |
| `DNS_COLLECTOR_API_URL` | برای تست Authoritative DNS | آدرس HTTPS سرویس ثبت‌کنندهٔ لاگ‌های Authoritative DNS |
| `DNS_COLLECTOR_API_TOKEN` | برای تست Authoritative DNS | توکن احراز هویت Bearer برای دریافت لاگ‌های Resolver از سرویس Collector |
| `DNS_COLLECTOR_API_TOKEN_PREVIOUS` | خیر (اختیاری) | توکن قبلی جهت چرخش بدون قطعی توکن (Token Rotation) |
| `DNS_UDP53_VERIFIED` | در Cloudflare Worker | تا پیش از راه‌اندازی و تأیید عملی شنوندهٔ UDP/53 باید `"false"` بماند |
| `ABUSEIPDB_API_KEY` | خیر (اختیاری) | کلید رسمی AbuseIPDB جهت استعلام واقعی سابقهٔ آدرس IP |
| `GEMINI_API_KEY` | خیر (اختیاری) | کلید سرویس Gemini جهت تولید گزارش تحلیلی فارسی (در صورت نبود یا خطا، گزارش مبتنی بر قواعد قطعی تولید می‌شود) |

## ۴. راهنمای راه‌اندازی زیرساخت Authoritative DNS و Cloudflare Worker

- یک **Cloudflare Worker معمولی مبتنی بر HTTP** به‌تنهایی نمی‌تواند بسته‌های خام `UDP/53` مربوط به Resolverهای DNS سیستم‌عامل کاربر را دریافت کند.
- برای فعال‌سازی تست کامل **Authoritative DNS Leak**:
  1. یک زیرشاخهٔ دامنه (مثلاً `dnsleak.example.com`) تعریف کنید و رکورد `NS` آن را به یک شنوندهٔ عمومی Authoritative DNS روی پورت `UDP/53` (اسکریپت `cloudflare/authoritative-dns-udp53.mjs`) متصل نمایید.
  2. شنوندهٔ Authoritative آدرس IP مبدا (Recursive Resolver) هر کوئری با الگوی استاندارد `p<N>.<runId>.<DNS_LEAK_DOMAIN>` را استخراج کرده و از طریق مسیر امن `POST /api/dns-collector/ingest` در `cloudflare/worker.ts` (با هدر `Authorization: Bearer <DNS_COLLECTOR_API_TOKEN>`) ثبت می‌کند.
  3. متغیرهای `DNS_LEAK_DOMAIN`، `DNS_COLLECTOR_API_URL`، `DNS_COLLECTOR_API_TOKEN` و پس از تأیید عملی، `DNS_UDP53_VERIFIED="true"` را تنظیم کنید.

## ۵. راهنمای تفسیر وضعیت‌ها و امتیاز امنیتی

| وضعیت (`TestStatus`) | برچسب فارسی | مفهوم دقیق فنی |
| :--- | :--- | :--- |
| `PASS` | موفق | تست اجرا شده و شواهد معتبر و کافی نشان می‌دهد در محدودهٔ همان تست نشتی مشاهده نشده است |
| `WARNING` | هشدار | ریسک احتمالی، اتصال مستقیم ISP، مشاهدهٔ IP محلی LAN یا باز بودن پورت عمومی وب (80/443) بدون اثبات نشت قطعی |
| `LEAK_DETECTED` | نشت شناسایی شد | شواهد ساختاری و معتبر از نشت IP، نشت DNS، نشت STUN در WebRTC یا باز بودن پورت بحرانی وجود دارد |
| `INCONCLUSIVE` | نامشخص | شواهد کافی برای اثبات امنیت یا نشت وجود ندارد (مانند دریافت نشدن کاندید STUN یا اسکن ناقص پورت‌ها) |
| `NOT_CONFIGURED` | پیکربندی نشده | زیرساخت خارجی مورد نیاز (مانند سرور Authoritative DNS یا کلید AbuseIPDB) تنظیم نشده است |
| `UNSUPPORTED` | پشتیبانی نشده | قابلیت مورد نظر (مانند `RTCPeerConnection`) در مرورگر یا محیط فعلی پشتیبانی نمی‌شود |
| `ERROR` | خطا در آزمون | خطا در اجرای تست؛ نتیجه قابل تأیید نیست (`Test execution failed; result cannot be verified.`) |

- **امتیاز حریم خصوصی (`privacyScore`):** فقط زمانی محاسبه می‌شود (`isScoreCalculable: true`) که هر سه تست الزامی پایه (**IP عمومی**، **Authoritative DNS** و **WebRTC STUN**) دارای شواهد معتبر باشند. در غیر این صورت، مقدار امتیاز `null` است و عبارت **«امتیاز قابل محاسبه نیست»** نمایش داده می‌شود.

## ۶. محدودیت‌های فنی مرورگر و پلتفرم (ویندوز و اندروید)

1. **محدودیت سندباکس مرورگر:** تست‌های وب صرفاً ترافیک عبوری از موتور مرورگر (HTTP/HTTPS و WebRTC) را مشاهده می‌کنند و نمی‌توانند جدول مسیریابی سطح کرنل سیستم‌عامل، وضعیت سایر نرم‌افزارهای نصب‌شده، نوع پروتکل تونل VPN یا قوانین فایروال سطح سیستم‌عامل را مستقیماً قرائت کنند.
2. **تفاوت نسخهٔ وب/PWA با فایل باینری بومی (Native Binary):**
   - این پروژه به‌صورت وب‌اپلیکیشن پیش‌رونده (**PWA / WebAPK**) برای نصب از طریق مرورگرهای مدرن روی **ویندوز ۱۰/۱۱** (Chrome / Edge) و **اندروید** طراحی شده است.
   - برای توزیع به‌عنوان فایل نصبی `.exe` / `.msi` در ویندوز یا `.apk` / `.aab` مستقل در مارکت‌های اندرویدی، بسته‌بندی جداگانه با ابزارهایی نظیر Electron/Tauri (ویندوز) یا Bubblewrap/Capacitor (اندروید) به همراه امضای دیجیتال کد (Code Signing) مورد نیاز است.
